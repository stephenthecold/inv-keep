# Inv-Keep — project state (handoff / context digest)

A self-contained summary so work can continue without the original chat history.
Read this + [CONFIGURATION.md](../CONFIGURATION.md) + [CHANGELOG.md](../CHANGELOG.md)
and you have the whole picture.

## What it is
A small, self-hosted, MSP-oriented inventory **charge-out** app. Scan/search an item
→ confirm quantity, client and job → it logs the charge-out, decrements stock, and
feeds a monthly **billing report** (cost vs client price vs margin). Independent of
Snipe-IT. Single SQLite DB.

## Stack
- **Backend**: Python, FastAPI, SQLAlchemy 2, Jinja2 templates (server-rendered).
- **DB**: SQLite file under `./data` (auto-migrates new columns on startup).
- **Auth**: UI-managed — none / OIDC (Authentik) / forward-auth. Built per-request
  with Authlib. `DISABLE_AUTH=1` env is a break-glass override.
- **Frontend**: vanilla JS (`app/static/app.js`), one CSS file. PWA (manifest + SW).
- **Deploy**: Docker Compose; optional bundled **Caddy** for TLS; or your own proxy.
- **Runtime deps**: see `requirements.txt`. `Pillow`/`pyyaml` are *build/dev only*
  (icons + YAML validation), NOT runtime deps.

## Data model (essentials)
- **Part** = an *Item* (UI label). Fields: name, icon (emoji), description, barcode
  (auto-generated if blank → printable label), type bulk|unique, **unit_cost** (our
  cost) + **unit_price** (client charge), qty, category, low-stock threshold.
- **Client** — table is still `customers` (preserves data through the rename). Full
  contact record. **Job** belongs to a client (ticket/WO ref).
- **Transaction** — a charge-out: part + client (`customer_id`) + optional `job_id`,
  qty, snapshots of cost & price at the time. `total_charge` / `total_cost` / `margin`.
- **AuditLog** — every sale/void/config change.
- **Setting** — key/value for all UI-configurable settings.

## Key decisions (why things are the way they are)
- **Standalone app, not Snipe-IT**: Snipe-IT has no "charge to a customer/job"
  concept; MSP billing needed it, so this is purpose-built.
- **Tables `customers`/`transactions.customer_id` kept** through the Customer→Client
  rename so existing installs upgrade in place. Migrations are additive
  (`ensure_columns`), never destructive.
- **Auth lives in the UI** (DB), only `DATABASE_URL`/`SESSION_SECRET`/`DISABLE_AUTH`
  are env. SessionMiddleware is added LAST so it's outermost (OIDC reads session).
- **Printing via OS dialog + CSS `@page`** sized per label preset — portable across
  Brother/DYMO/Zebra/Rollo without per-printer drivers. Label content is configurable
  (icon/name/price/desc/category/company/extra, barcode digits on/off).
- **PWA now, TWA APK as framework**: keyboard-wedge AIO scanners work in the browser/
  PWA; the APK is generated by Bubblewrap from `android/twa-manifest.json`.
- **TLS three ways**: bundled Caddy auto (Let's Encrypt), bundled Caddy with your own
  cert (`Caddyfile.custom` + `certs/`), or external proxy (expose `APP_PORT`).

## Run / build / deploy
- Install: `./install.sh` (or `-y`). Manual: `docker compose up -d --build`
  (`--profile ssl` for HTTPS). Details: [DEPLOY.md](DEPLOY.md).
- Local dev: `uvicorn app.main:app --reload` with `DATABASE_URL=sqlite:///./data/app.db`.
- Regenerate icons (rare): `pip install pillow && python scripts/make_icons.py`.

## Cutting a release (the versioning workflow)
1. Bump `app/version.py`.
2. Add a `CHANGELOG.md` entry.
3. Commit, then `git tag -a vX.Y.Z -m "Inv-Keep vX.Y.Z"`.
Current: **v1.3.0** (tags: v1.0.0 → v1.3.0).

## Verified each release
byte-compile (`python -m py_compile app/*.py`), `node --check app/static/app.js`,
run + curl all pages (expect 200, no tracebacks), and key flows in a real browser
(scan→charge, labels, settings). YAML/JSON validated. No secrets/DBs committed.

## Known limitations / not built (good next tasks)
- **Email OAuth** (MS/Google) is implemented but only the **SMTP** path was live-
  tested (no real OAuth creds available).
- **Printing** uses the OS dialog — no one-tap *silent* printing or raw ZPL/ESC-P.
- **Native** scanner *intent* (DataWedge) consumption would need a Capacitor wrapper.
- **APK** must be built on a machine/CI with Android tooling (workflow provided).
- **LICENSE/author** are placeholders ("Inv-Keep contributors", MIT) and TWA
  `packageId` is `com.invkeep.twa` — set real values before publishing.
- Monthly scheduler is **in-process** (fine for a single container; not multi-replica).
